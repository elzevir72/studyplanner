# Frontend — 가이드

React + TypeScript SPA. S3 + CloudFront로 정적 호스팅. API 계약은 [../docs/api.md](../docs/api.md) 참고.

## 원칙
- **모바일 우선 반응형** — 매일 짧게 기록하는 습관형 도구라 모바일 사용 비중이 높을 것으로 예상. 네이티브 앱은 만들지 않고(스토어 배포/보안 검토 부담) 반응형 웹으로 모바일 사용성을 최우선으로 설계한다.
- 화면은 최소 4개로 시작: (1) 사용자 선택 + PIN 입력, (2) 개인 기록 입력/조회 (목표 설정/수정, PIN 변경 UI 포함), (3) 그룹 대시보드, (4) 관리자 화면(`/admin`, 참가자 흐름과 별도 경로 — 메인 네비게이션에 링크 노출 안 함).
- 사용자 선택 화면(1)의 드롭다운은 `status="active"`인 유저만 보여준다.
- 개인 기록 화면에서 목표(`daily_goal`, 값+단위)를 설정/수정할 수 있어야 하고, 기록 입력 시 저장된 달성률(%)을 보여준다. 단위가 목표와 다른 기록은 "달성률 계산 불가" 정도로 자연스럽게 표기(에러 아님). PIN 변경 기능도 이 화면에 둔다.
- 대시보드에는 현재 시즌 이름/기간을 표시하고, 주/격주/월간 뷰 외에 "이번 시즌 전체" 뷰도 제공한다. 참가자별 달성률(%)을 `entry_count`와 함께 보여주되, 개인 비교/순위 매기는 톤은 피하고 담백하게 표기한다.
- 대시보드와 개인 기록 화면 상단에 현재 시즌의 `exam_date` 기준 D-day 배너("OO 시험까지 OO일 남았습니다")를 표시한다. `exam_date`가 없으면 배너 자체를 숨긴다.
- 관리자 화면(4): 참가자 계정 생성(초기 PIN 지정)/상태 변경, 시즌 생성/전환 폼을 제공. 참가자용 인증 상태와 완전히 분리해서 관리한다(같은 브라우저에서 참가자 로그인 중이어도 서로 영향 없어야 함).
- 상태 관리 라이브러리는 규모상 과설계 금지 — React 기본 상태 + fetch로 충분하면 Redux 등 도입하지 않는다.
- 로그인 토큰은 짧은 TTL이므로 만료 시 자연스럽게 사용자 선택 화면으로 리다이렉트되도록 처리.
- 대시보드에서 "미수행자" 등 그룹 정보는 압박감을 주지 않는 톤으로 표기한다 (이 도구의 목적은 성과 관리가 아니라 공유 촉진).
