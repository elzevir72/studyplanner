# Frontend — 가이드

React + TypeScript SPA. S3 + CloudFront로 정적 호스팅. API 계약은 [../docs/api.md](../docs/api.md) 참고.

## 원칙
- **모바일 우선 반응형** — 매일 짧게 기록하는 습관형 도구라 모바일 사용 비중이 높을 것으로 예상. 네이티브 앱은 만들지 않고(스토어 배포/보안 검토 부담) 반응형 웹으로 모바일 사용성을 최우선으로 설계한다.
- 화면은 최소 3개로 시작: (1) 사용자 선택 + PIN 입력, (2) 개인 기록 입력/조회 (목표 설정/수정 UI 포함), (3) 그룹 대시보드.
- 사용자 선택 화면(1)의 드롭다운은 `status="active"`인 유저만 보여준다.
- 개인 기록 화면에서 목표(`daily_goal`, 값+단위)를 설정/수정할 수 있어야 하고, 기록 입력 시 저장된 달성률(%)을 보여준다. 단위가 목표와 다른 기록은 "달성률 계산 불가" 정도로 자연스럽게 표기(에러 아님).
- 대시보드에는 현재 시즌 이름/기간을 표시하고, 주/격주/월간 뷰 외에 "이번 시즌 전체" 뷰도 제공한다.
- 상태 관리 라이브러리는 규모상 과설계 금지 — React 기본 상태 + fetch로 충분하면 Redux 등 도입하지 않는다.
- 로그인 토큰은 짧은 TTL이므로 만료 시 자연스럽게 사용자 선택 화면으로 리다이렉트되도록 처리.
- 대시보드에서 "미수행자" 등 그룹 정보는 압박감을 주지 않는 톤으로 표기한다 (이 도구의 목적은 성과 관리가 아니라 공유 촉진).
