# Requirements — 입력폼 요약/펼침 개선

## Intent Analysis Summary

- **User Request**: "학습입력폼이 구린가?" → "시각적/구조적으로 복잡해 보임" → 학습 수단 블록을 아코디언처럼 요약/펼침 가능하게 개선
- **Request Type**: Enhancement (기존 기능의 UX 개선, 데이터 모델/API 변경 없음)
- **Scope Estimate**: Single Component — `frontend/src/pages/EntryPage.tsx`의 학습 수단 렌더링 부분만 (신규 재사용 컴포넌트 1개 추가)
- **Complexity Estimate**: Simple — 상태 로직은 기존 값(`method`, `amount.value`)에서 파생되며 신규 상태 최소화
- **Depth**: Minimal (요구사항이 대화로 이미 명확히 좁혀짐, 질문 6개 전부 애매성 없이 답변 완료)

## Functional Requirements

### FR-1. 학습 수단 블록의 요약/펼침 전환
- 학습 수단 블록(`study-item-block`)은 "완료" 여부에 따라 **펼친 상태(전체 필드)**와 **접힌 상태(요약 한 줄)** 두 가지로 렌더링된다.
- **완료 기준**: `item.method`가 있고 `item.amount.value > 0`일 때 (Q1-1=B) — 기존 저장 검증 로직(`method && amount.value > 0`)과 동일한 기준을 재사용한다.
- 완료되지 않은 블록은 학습 내용(topics) 선택 여부와 무관하게 계속 펼쳐진 상태를 유지한다.

### FR-2. 접힘 트리거 시점
- 접힘은 실시간(값 변경 즉시, blur 등)으로 발생하지 않는다 (Q1-2=B).
- 접힘 판정은 다음 두 시점에만 이루어진다:
  1. **"+ 학습 수단 추가" 클릭 시** — 이 시점에서 완료 기준을 만족하는 기존 블록들만 접힌 상태로 전환되고, 새 블록이 펼쳐진 채로 추가된다.
  2. **기록 로드 시** (신규/수정 진입) — FR-4 참고.
- 미완료 블록은 "+ 학습 수단 추가"를 눌러도 강제로 접히지 않고 계속 펼쳐진 채 유지된다 (Q2-1=A).

### FR-3. 요약줄 클릭 시 재편집
- 접힌 요약줄을 클릭하면 다시 펼쳐져서 수정 가능한 상태가 된다.
- 다시 클릭하면(또는 다른 블록이 새로 완료되면) 다시 접힐 수 있다 — 아코디언과 동일한 토글 상호작용.
- 별도의 "수정" 버튼은 두지 않는다 — 요약줄 자체가 클릭 가능한 토글이다.

### FR-4. 기존 기록 로드 시 초기 상태
- "다른 날짜 기록 보기/수정"으로 과거 기록을 불러올 때, 저장된 학습 수단 항목들은 **전부 접힌 상태(요약줄)**로 초기 렌더링된다 (Q3-1=A).
- 근거: 저장된 기록의 각 항목은 이미 `method`와 `amount.value > 0`을 만족하므로(FR-1 기준상 자동으로 "완료" 상태), 별도 로직 없이 자연스럽게 접힌 채 시작한다.
- 오늘 신규 기록을 처음 작성할 때(빈 상태)는 첫 블록이 당연히 미완료이므로 펼쳐진 채 시작한다 — 이는 기존 동작과 동일.

### FR-5. 요약줄 표시 형식
- 형식: `{학습 수단} · {학습 내용, 콤마로 구분} · {학습량}{단위}`
- 학습 내용(topics)이 비어있으면 해당 구간과 구분자(·)를 함께 생략한다 — 예: `인강 · 30분` (topics 없을 때), `인강 · 문법,청해 · 30분` (topics 있을 때) (Q4-1=A)
- 구현 힌트: `[method, topics.join(','), amountText].filter(Boolean).join(' · ')`

### FR-6. 적용 범위
- 이번 변경은 **"오늘 기록" 폼(학습 수단 블록)에만** 적용한다 (Q5-1=A).
- "목표 설정" 폼의 동일 구조 블록(수단+목표량)은 이번 범위에서 제외한다 — 향후 필요 시 별도 요청으로 확장.
- 단, 신규 컴포넌트는 목표 설정에서도 재사용 가능하도록 일반화된 props로 설계한다(권장, 강제 아님) — 지금 당장 적용하지 않더라도 나중에 확장하기 쉽게.

## Non-Functional Requirements

- **NF-1 (기능 변경 없음)**: 이 변경은 순수 UI 상호작용 개선이며, 저장되는 데이터 구조(`StudyItem`)나 API 계약에는 영향을 주지 않는다.
- **NF-2 (기존 검증 로직 재사용)**: 접힘 판정 기준은 기존 저장 검증 로직과 동일한 조건식을 사용해 두 로직이 어긋나지 않도록 한다.
- **NF-3 (컴포넌트 경계)**: 이번 변경으로 인한 신규 상태(펼침/접힘)는 `EntryPage.tsx` 내부(또는 신규 하위 컴포넌트) 범위에 한정하고, 전역 상태나 API 응답 형태에 영향을 주지 않는다.
- **NF-4 (접근성/기존 관례 준수)**: 기존 `Accordion` 컴포넌트가 이미 `<details>`/`<summary>` 기반으로 구현되어 있으므로, 가능하면 그 컴포넌트를 재사용하거나 동일한 상호작용 패턴(클릭 토글)을 따른다.

## Out of Scope

- "목표 설정" 폼에 동일 패턴 적용 (Q5-1=A로 명시적 제외, 컴포넌트 재사용 가능성만 열어둠)
- 데이터 모델, API, 백엔드 변경 — 전무
- 학습 수단 삭제/추가 버튼의 위치나 동작 변경 — 이번 범위 밖(요약/펼침 전환에만 집중)
