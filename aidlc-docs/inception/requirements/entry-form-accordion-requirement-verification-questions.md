# Requirement Verification Questions — 입력폼 요약/펼침 개선

대화로 이미 핵심 방향은 정해졌습니다: `EntryPage.tsx`의 학습 수단 블록(`study-item-block`)을 아코디언처럼 만들어, 수단 선택 전엔 "학습 수단" 태그만 보이고, 선택 후 나머지 필드(학습 내용/학습량)가 펼쳐지며, 완료된 블록은 요약 한 줄(`인강 · 문법,청해 · 30분`)로 접혀서 클릭하면 다시 펼쳐지는 구조입니다.

세부 동작을 확정하기 위해 몇 가지 질문이 남았습니다.

---

## 1. "완료(접힘 가능)" 상태의 기준

**Q1-1.** 학습 수단 블록이 언제 "완료"로 간주되어 요약 줄로 접혀야 할까요?

A) 학습 수단(method)만 선택되면 즉시 접을 수 있음 — 학습량이 0이어도 "인강 · (내용 없음) · 0분"처럼 표시
B) 학습 수단 + 학습량(value > 0)까지 채워져야 접을 수 있음 — 그 전엔 계속 펼쳐진 상태 유지 (학습 내용은 선택 안 해도 무방, 필수 아님)
C) 사용자가 명시적으로 "접기" 액션을 취해야만 접힘 — 자동으로는 절대 안 접힘

> 💡 **페르소나별 추천**
> - **PM**: **B**. 학습량 없이 접히면 "기록을 다 채웠다"는 착각을 줄 수 있어 위험하고(저장 시 `amount.value > 0`이 유효성 기준이므로), 반대로 매번 수동으로 접어야 하면(C) 이번 개선의 목적(자동으로 짧아지는 폼)이 퇴색됨.
> - **10년차 개발자**: **B**. 기존 저장 검증 로직(`validItems = studyItems.filter(item => item.method && item.amount.value > 0)`)과 "접힘 가능" 기준을 동일하게 맞추면 새 상태 변수 없이 기존 값만으로 판단 가능 — 구현이 단순해지고 두 규칙이 어긋날 여지가 없음.
> - **기획자**: **B**. 사용자가 수단 선택 후 학습량까지 입력을 마치면 자연스럽게 다음 수단으로 넘어가고 싶어할 시점이라, 그 타이밍에 자동으로 접히는 게 흐름에 맞음.

[Answer]: B

**Q1-2.** 자동으로 접히는 시점은 정확히 언제인가요? (Q1-1=B를 전제로)

A) 학습량 입력 필드에서 포커스가 벗어날 때(blur) 조건 충족 시 자동 접힘
B) 별도 트리거 없음 — 조건이 충족된 상태에서 사용자가 요약줄 형태를 보고 싶으면 그냥 다음 동작(다른 수단 추가 등)으로 넘어감, 실제 "접힘 렌더링"은 그 블록이 처음 로드/재방문될 때만 결정 (즉 이미 값이 있는 기존 기록을 불러올 때는 접힌 채로 시작, 새로 입력 중인 것은 계속 펼쳐진 채 유지하다가 "+ 학습 수단 추가" 클릭 시 그 시점 기준으로 이전 블록들을 접음)

> 💡 **페르소나별 추천**
> - **PM**: **B**. A(blur 트리거)는 사용자가 필드 하나 건드릴 때마다 레이아웃이 튀어서(값 입력 중 갑자기 접히면) 오히려 산만할 수 있음. B처럼 "새 수단을 추가하는 시점"에 자연스럽게 이전 것들이 정리되는 편이 예측 가능함.
> - **10년차 개발자**: **B**. blur 이벤트 기반(A)은 사용자가 실수로 다른 곳을 클릭했다가 다시 돌아와야 하는 경우 등 엣지케이스가 많아 상태 관리가 복잡해짐 — "+ 학습 수단 추가" 클릭 시점에만 판단하는 게 훨씬 단순하고 버그 여지가 적음.
> - **기획자**: **B**. 사용자 입장에서 "다음 수단 추가하기" 버튼을 누르는 행위 자체가 "이전 건 다 됐다"는 의사표시이므로 그 타이밍에 정리되는 게 직관적임.

[Answer]: B

## 2. 새 학습 수단 추가 시 동작

**Q2-1.** "+ 학습 수단 추가" 버튼을 누르면, 기존에 이미 펼쳐진 채로 남아있던 미완료 블록들은 어떻게 될까요? (예: 3번째 수단을 추가로 누르는데 1번째가 아직 학습량 미입력 상태인 경우)

A) 완료된(Q1-1 기준 충족) 블록만 접히고, 미완료 블록은 그대로 펼쳐진 채 유지 — 새 블록이 그 아래 추가로 펼쳐짐
B) 무조건 새 블록만 펼치고 나머지는 전부 접음(미완료여도) — 미완료 상태는 요약줄에 "(입력 중)" 등으로 표시

> 💡 **페르소나별 추천**
> - **PM**: **A**. 미완료 데이터를 강제로 접으면 사용자가 "어? 방금 쓰던 게 사라졌나" 오해하기 쉬움. 완료된 것만 자동 정리하고 나머지는 그대로 두는 게 안전함.
> - **10년차 개발자**: **A**. Q1-1=B로 "접힘 = method && amount.value>0"이 이미 정의돼 있으니, 이 규칙을 그대로 각 블록에 적용하면 자연스럽게 A가 나옴 — 별도 "입력 중" 상태를 추가로 관리할 필요가 없어 구현이 단순함.
> - **기획자**: **A**. 사용자가 여러 수단을 오가며 입력할 수도 있는데(예: 인강 학습량 입력하다가 잠깐 문제집 수단을 추가하고 다시 돌아옴), 강제로 접으면 이런 자연스러운 흐름을 막게 됨.

[Answer]: A

## 3. 기존 기록 불러오기(수정 모드) 시 초기 상태

**Q3-1.** 이미 저장된 기록을 불러와서 수정할 때(예: "다른 날짜 기록 보기"에서 과거 날짜 선택), 여러 학습 수단이 저장되어 있다면 초기 화면에서 몇 개가 펼쳐진 상태로 시작해야 할까요?

A) 전부 접힌 상태로 시작 (요약줄만 쭉 나열) — 수정하고 싶은 것만 클릭해서 펼침
B) 전부 펼쳐진 상태로 시작 (기존 동작과 동일) — 접기는 새로 입력할 때만 발생

> 💡 **페르소나별 추천**
> - **PM**: **A**. 이번 개선의 목적 자체가 "여러 수단이 쌓였을 때 화면이 길어지는 것"을 줄이는 것이므로, 기존 기록을 불러올 때도 접힌 상태로 시작해야 개선 효과가 실제로 체감됨 — B로 하면 정작 수단이 많은 과거 기록을 다시 볼 때는 개선 전과 똑같음.
> - **10년차 개발자**: **A**. `getEntry` 응답을 받아 `studyItems`를 세팅하는 시점에 이미 각 항목이 `method`+`amount.value>0`을 만족하므로(저장된 기록이니 당연히), Q1-1의 접힘 조건이 자동으로 전부 참이 되어 별도 로직 없이 A가 자연스럽게 나옴.
> - **기획자**: **A**. 과거 기록을 다시 열어봤을 때 한눈에 "그날 뭘 했는지" 요약으로 훑어보고, 수정하고 싶은 항목만 펼치는 흐름이 훨씬 깔끔함.

[Answer]: A

## 4. 요약줄에 표시할 정보

**Q4-1.** 요약줄 형식을 `인강 · 문법,청해 · 30분`으로 예시 드렸는데, 실제 구현 시 다음을 확정합니다.

A) `{수단} · {내용 콤마구분, 없으면 생략} · {학습량} {단위}` — 내용이 없으면 가운데 구분자(·)도 함께 생략 (예: `인강 · 30분`)
B) 내용이 없어도 자리 유지 — `인강 · (내용 없음) · 30분`

> 💡 **페르소나별 추천**
> - **PM**: **A**. 학습 내용(topics)은 선택 안 해도 되는 필드인데 "(내용 없음)"이라고 매번 노출하면 마치 뭔가 빠뜨린 것처럼 보여 불필요한 불안감을 줄 수 있음 — CLAUDE.md의 "압박감 주지 않는 톤" 원칙과도 맞닿음.
> - **10년차 개발자**: **A**. `[method, topics.join(','), amountText].filter(Boolean).join(' · ')` 형태로 빈 값 자동 제거가 구현도 더 간단함.
> - **기획자**: **A**. 짧고 읽기 편한 한 줄 요약이 목적이므로, 없는 정보를 굳이 자리 차지하며 보여줄 필요가 없음.

[Answer]: A

## 5. 적용 범위

**Q5-1.** 이 아코디언화를 "목표 설정" 폼(`Accordion summary="목표 설정"` 안의 수단별 목표 블록)에도 동일하게 적용할까요? 구조가 거의 동일합니다(수단+목표량 반복).

A) 이번엔 "오늘 기록" 폼만 — 목표 설정은 자주 안 쓰는 화면(한 번 설정하면 잘 안 바꿈)이라 범위 밖
B) 목표 설정 폼도 동일하게 적용 — 구조가 같으니 한 번에 처리

> 💡 **페르소나별 추천**
> - **PM**: **A**. "구리다"고 지적하신 게 매일 쓰는 "오늘 기록" 폼이었고, 목표 설정은 애초에 아코디언(`목표 설정`) 안에 접혀 있어 이미 기본적으로 안 보이는 화면 — 지금 급한 건 아님. 범위를 좁혀서 빠르게 검증하고, 반응이 좋으면 다음에 목표 설정도 확장하는 게 안전.
> - **10년차 개발자**: **A, 컴포넌트는 재사용 가능하게 설계**. 오늘 기록에서 만들 새 컴포넌트(예: `CollapsibleStudyItem`)를 목표 설정에서도 나중에 재사용할 수 있게 props를 일반화해두면, 이번엔 오늘 기록에만 적용해도 나중 확장이 쉬움.
> - **기획자**: **A**. 목표 설정은 이미 아코디언 뒤에 숨어있어 접근 빈도 자체가 낮으니, 사용자가 매일 느끼는 불편함(오늘 기록)부터 해결하는 게 체감 효과가 큼.

[Answer]: a
